# История изменений

Изменения в каждом выпуске OpenXPlay Relay, начиная с самых новых. Приложение для Android и Linux-ретранслятор выпускаются отдельно; в заголовках выпусков для Linux указано «Linux», а в заголовках записей о приложении для iPhone — «приложение для iPhone». Пакеты и контрольные суммы находятся в [Releases](https://github.com/OpenXPlay/OpenXPlay-Relay/releases) на GitHub; установка и настройка начинаются с раздела [Быстрый старт](/ru/quick-start).

## Открытое бета-тестирование приложения для iPhone {#iphone-beta}

2026-11-05 · [Присоединиться через openxplay.com](https://openxplay.com/ru/)

Приложение OpenXPlay для iPhone подключает iPhone к головному устройству напрямую, без ретранслятора. Как и ретранслятор, оно показывает CarPlay в браузере головного устройства, в Carlink, CarLife или приёмнике трансляции. Присоединяйтесь к открытому бета-тестированию через [openxplay.com](https://openxplay.com/ru/) или по QR-коду на [главной странице](/ru/#iphone-app).

## 0.2.6 {#v0-2-6}

2026-11-04 · [Скачать](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.6)

Приложение для Android: ручная настройка размера CarPlay, ширины экрана и областей отображения, напоминание в мастере настройки проверить режим экономии данных на iPhone и больше никаких предупреждений о сертификате доверенного HTTPS на Android 10 и более ранних версиях.

**Новое**

- Приложение для Android: Settings → CarPlay picture → *Resolution* предлагает *Automatic* или *Manual*. В ручном режиме задаются ширина, высота и плотность, а также показывается размер, который сейчас использовал бы автоматический режим, — его можно сразу подставить.
- Приложение для Android: у ширины экрана CarPlay появился вариант *Custom* — от 100 до 400 мм с шагом 5 мм; показывается ширина, которую сейчас объявляет автоматический режим.
- Приложение для Android: Settings → Car → *CarPlay view areas* предлагает *Automatic* или *Manual*. В ручном режиме задаётся полноэкранный и/или оконный размер и показываются размеры, чаще всего встречавшиеся у этого головного устройства.

**Изменения**

- Приложение для Android: в мастере настройки кнопка Next на странице сети напоминает после подключения iPhone проверить, что для этой сети Wi-Fi на iPhone выключен режим экономии данных («Настройки» → Wi-Fi → ⓘ). То же самое говорят страница сети и сообщение, которое показывается, когда iPhone не подключается к Wi-Fi.
- Приложение для Android: при точке доступа этого телефона мастер настройки просит выбрать *Copy to settings* или *Use my existing hotspot*, прежде чем нажать Next; ни один вариант не выбран заранее.
- Приложение для Android: [доверенный HTTPS](/ru/trusted-https) больше не вызывает предупреждений о сертификате на Android 10 и более ранних версиях, если настроен действительный сертификат домена, и использует сертификат только в пределах начала и конца срока его действия.

**Примечания**

- Включает всё из 0.2.6-beta.1 и 0.2.6-beta.2.
- Новые настройки размера и ширины применяются при следующем подключении CarPlay. Области отображения работают только с автоматическим размером CarPlay.
- Страница головного устройства по-прежнему предлагает четыре предустановленных значения ширины; выбор другого из них там сбрасывает пользовательскую ширину. Developer options → *Physical width (calibration)*, если включено, имеет приоритет над пользовательской шириной; по умолчанию выключено.
- Полные примечания к выпуску: [GitHub Releases](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.6).

## 0.2.5 {#v0-2-5}

2026-11-02 · [Скачать](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.5)

Приложение для Android: вывод в CarLife, беспроводной дисплей как вывод с управлением на телефоне и DiPlay 0.2.22.

**Новое**

- Приложение для Android: вывод в [CarLife](/ru/carlife) (экспериментально). Изображение и сенсорное управление CarPlay передаются в CarLife автомобиля через ту же сеть Wi-Fi, точку доступа этого телефона или USB-подключение в режиме аксессуара; звук остаётся на Bluetooth-соединении iPhone с автомобилем. Выберите его в мастере настройки или в Settings → Output; IP-адрес автомобиля указывать не обязательно.
- Приложение для Android: [беспроводной дисплей](/ru/wireless-display) (DLNA, Miracast) можно выбрать в мастере настройки и в Settings → Output, с пометкой *Experimental*. Автомобиль показывает только изображение; если используется только беспроводной дисплей, CarPlay показывается на этом телефоне и управляется касаниями на нём, с кнопкой «Назад», а главный экран во время подключения предлагает *Show CarPlay*.
- Приложение для Android: журналы сохраняют хронологию подключения, даже когда системный журнал теряет записи, а экспорт сообщает, если запись неполная.

**Изменения**

- Приложение для Android: вывод в приложение Carlink больше не помечен как *Experimental* в мастере настройки и в Settings → Output.
- Приложение для Android: беспроводной дисплей через DLNA передаёт все звуки CarPlay (оповещения, Siri, звонки), а не только музыку, когда звук через Bluetooth автомобиля выключен.
- Приложение для Android: беспроводной дисплей следует настройке Settings → CarPlay picture → *Resolution*; DLNA сам объявляет экран автомобиля.
- Приложение для Android: с DLNA автомобиль больше не застревает на старом кадре после свайпа, а подключившийся рендерер начинает со свежего изображения.
- Приложение для Android: на странице головного устройства касание снова восстанавливает полноэкранный режим, вход в полноэкранный режим и выход из него больше не перезапускают CarPlay (Samsung Internet), а кадры, пришедшие пачкой, показываются, а не отбрасываются.
- Приложение для Android: Carlink даёт медленным головным устройствам 4 с на ответ на запрос MTU (XPeng G9 отвечает за 1,8 с), поэтому подключение больше не обрывается на этапе обнаружения служб. Спасибо, hellowalker.
- Приложение для Android: на телефонах Xiaomi с Android 10 или 11 предварительное сканирование Wi-Fi для Carlink выполняется не чаще раза в 2 минуты, оставляя сканирования системному диалогу Wi-Fi, поэтому подключение к Wi-Fi автомобиля реже завершается ошибкой. Спасибо, hellowalker.
- Приложение для Android: DiPlay 0.2.22. Проводной CarPlay подключается с первой попытки после переподключения кабеля; беспроводной запуск повторяется сразу после включения Bluetooth; объявление CarPlay в точке доступа больше не ждёт около 20 с; беспроводная музыка сохраняет скорость iPhone (без заиканий); USB-микрофон записывает речь, а не тишину; жесты несколькими пальцами стали стабильнее; подключения и получаемые данные проверяются строже.
- Приложение для Android: [доверенный HTTPS](/ru/trusted-https) учитывает ограничения частоты запросов центра сертификации отдельно для каждого имени, учётной записи или среды, а сертификаты на 45 и 64 дня продлеваются вовремя.

**Примечания**

- Включает всё из 0.2.5-beta.1 и 0.2.5-beta.2.
- Полные примечания к выпуску: [GitHub Releases](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.5).

## Linux 0.1.6 {#linux-v0-1-6}

2026-11-01 · [Скачать](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/linux-v0.1.6)

Linux-ретранслятор: первый выпуск после 0.1.3. Страница администрирования получила дизайн приложения для Android, рассчитанный в первую очередь на телефон, CarPlay подстраивается под браузер головного устройства, Carlink работает на втором адаптере Wi-Fi, появились проводной CarPlay и доверенный HTTPS, а OpenXPlay Flasher устанавливает и обновляет ретранслятор.

**Новое**

- Страница администрирования получила дизайн приложения для Android, рассчитанный в первую очередь на телефон, в светлом и тёмном оформлении. Главный экран показывает подключение как одну цепочку iPhone → этот ретранслятор → автомобиль, и каждый шаг открывает свои подробности и способ исправления; шестерёнка вверху главного экрана открывает настройки с меню как в приложении для Android. После входа с паролем по умолчанию страница просит задать собственный (это можно пропустить).
- При сопряжении с iPhone ретранслятор называется так, как его показывает iPhone, — OpenXPlay Linux. Сопряжённые устройства можно удалить на главном экране и в Settings → iPhone connection.
- Проводной CarPlay: Settings → iPhone connection → USB cable, когда iPhone подключён к порту USB-A на ретрансляторе кабелем USB-A — Lightning или USB-A — USB-C; головное устройство по-прежнему связывается с ретранслятором по Wi-Fi. Беспроводное подключение остаётся вариантом по умолчанию.
- Области отображения CarPlay, включены по умолчанию: когда браузер головного устройства входит в полноэкранный режим или выходит из него, CarPlay перестраивает раскладку под новый размер без переподключения и без чёрных полос.
- Settings → CarPlay picture: Resolution, CarPlay screen width, Video codec и Frame rate, также в настройках страницы головного устройства. После выхода браузера головного устройства из полноэкранного режима, например для камеры заднего вида, одно касание возвращает его обратно.
- Settings → Car and screen: выбор автомобиля по марке, модели и году из каталога приложения для Android (с ZEEKR), с сохранением экранов для каждого автомобиля.
- Settings → Audio → CarPlay audio over the car’s Bluetooth (экспериментально), включено по умолчанию: музыка, навигация и звонки воспроизводятся через собственное Bluetooth-соединение iPhone с автомобилем. Если звук вместо этого идёт из iPhone, выключите эту настройку.
- Интерфейсы и сетевые роли: ретранслятор показывает каждый интерфейс Ethernet и Wi-Fi с его возможностями и выбирает интерфейс для iPhone, браузера головного устройства и Carlink; каждый можно выбрать и вручную. Диапазон и канал точки доступа определяются оборудованием Wi-Fi, есть настройки Wi-Fi country и Hotspot security (по умолчанию WPA2).
- Carlink работает на втором адаптере Wi-Fi, поэтому точка доступа CarPlay не отключается, пока он подключается к автомобилю. Carlink запоминает, как каждый автомобиль передаёт подключение, продолжает сканирование, пока автомобиль не появится, и передаёт на iPhone мультимедийные кнопки на руле.
- Точка доступа администрирования (по умолчанию выключена, нужен второй адаптер Wi-Fi): после включения она отдаёт страницу администрирования по адресу `https://10.79.0.1:6975` и приостанавливается, пока этот адаптер использует Carlink.
- [Доверенный HTTPS](/ru/trusted-https) и [адаптация для браузера Tesla](/ru/tesla), как на Android, по умолчанию выключены.
- Logs, Configuration files и Check for updates, как на Android: сохраните журналы в ZIP-архив или отправьте их на logs.openxplay.org; ретранслятор обращается к GitHub только при нажатии Check for updates.
- Identity and certificates: импорт или удаление идентификатора аксессуара Apple (файлы или ZIP-архив) либо использование удалённого сервера MFi или чипа аутентификации по I2C или через адаптер CH341.
- Experimental, всё включено по умолчанию, в том числе три переключателя для iPhone, например на iOS 16, которые подключаются, но так и не показывают изображение, и Watch for stalls. Если подключение стало хуже, выключите Use experimental options.
- Каждый выпуск содержит пакет Debian и манифест установки, с помощью которых [OpenXPlay Flasher](/ru/ufi003-relay#install) устанавливает и обновляет ретранслятор. Другие хосты можно описать в профиле хоста `/etc/openxplay/host.json`; см. [Другие устройства с Linux](/ru/linux-devices).

**Изменения**

- С одним радиомодулем Wi-Fi, как у UFI003, ретранслятор предлагает только вывод в браузер; для Carlink нужен второй адаптер Wi-Fi. Как только второй адаптер появляется, Carlink начинает работать без перезапуска.
- У страницы администрирования своё имя в каждой сети: `openxplay-car.local` в сети iPhone и `openxplay-admin.local` в остальных, например в Ethernet или в точке доступа администрирования; `openxplay-linux.local` по-прежнему работает. Адрес, введённый без `https://`, по-прежнему открывает страницу.
- Точка доступа CarPlay и точка доступа администрирования используют пароль `openxplay`, если вы не задали свой на странице администрирования. Пароль точки доступа, сгенерированный более ранней версией, при обновлении меняется на `openxplay`, а имя остаётся прежним, поэтому головному устройству один раз понадобится новый пароль.
- Точка доступа CarPlay работает всё время, пока работает ретранслятор, в том числе после неудачного запуска или Stop, поэтому страница администрирования остаётся доступной в автомобиле.
- Connect automatically запускается, когда всё готово, после пятисекундного обратного отсчёта, который отменяет Not now; Start on device boot — отдельная настройка.
- После того как iPhone найден, неудачный запуск повторяется пять раз, затем останавливается с отчётом и делает ещё одну попытку, когда снова становятся доступны Bluetooth, Wi-Fi, Carlink или iPhone.
- Carlink использует один и тот же идентификатор при передаче через Bluetooth и в сеансе, поэтому после обновления автомобиль один раз запросит код Carlink.
- Ретранслятор сообщает свою настоящую версию (0.1.3 сообщал 0.1.2). Отсутствие интерфейса Wi-Fi больше не останавливает его; страница администрирования остаётся доступной через Ethernet.

**Примечания**

- Включает всё из бета-версий Linux 0.1.5 и 0.1.6.
- После обновления с 0.1.3 один раз обновите страницу на головном устройстве; при последующих обновлениях она перезагружается автоматически.
- Перед возвратом к 0.1.3 верните копию `/var/lib/openxplay/settings.json`, сделанную до обновления, или удалите этот файл; 0.1.3 не запускается с настройками, которые записывает эта версия.
- Известные проблемы: в некоторых браузерах головных устройств страница показывает меньше кадров, чем получает, — это исследуется; Experimental → Suggest working modes пока ничего не делает в Linux.
- На GitHub выпуск с пометкой Latest — всегда приложение для Android; теги выпусков для Linux начинаются с `linux-v`.
- Полные примечания к выпуску: [GitHub Releases](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/linux-v0.1.6).

## 0.2.4 {#v0-2-4}

2026-11-01 · [Скачать](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.4)

Приложение для Android: более плавные экраны, кнопка на главном экране, реагирующая на первое касание, параметры точки доступа для копирования в настройки телефона и исправление Bluetooth для некоторых телефонов с MIUI на Android 12.

**Новое**

- Приложение для Android: когда iPhone подключается через точку доступа этого телефона, Settings → Network предлагает два способа настроить точку доступа. *Copy to settings (recommended)* предлагает имя (OpenXPlay-A-…) и 16-символьный пароль; каждая кнопка копирует одно из них и открывает настройки точки доступа телефона. *Use my existing hotspot* сохраняет точку доступа, которую вы настроили сами: введите там её имя и пароль. Мастер настройки предлагает тот же выбор, а уже сохранённые параметры точки доступа остаются без изменений.

**Изменения**

- Приложение для Android: более плавные экраны. Измерено на Redmi 14C (HyperOS) с открытым главным экраном и без подключённого автомобиля; на других телефонах результаты будут иными:
  - Пока ретранслятор ищет автомобиль, *Record all Bluetooth advertisements* (Experimental) больше не работает в потоке, который отрисовывает экраны. Процессорное время этого потока в простое снижается с 64–119 мс до 25–27 мс в секунду, на 60–77% меньше.
  - Кнопка на главном экране срабатывает с первого касания. Раньше касание в течение 0,5 с после появления кнопки, например сразу после возврата из настроек, игнорировалось; теперь срабатывают 4 таких касания из 4.
  - Пока сеанс Carlink автомобиля не готов, два потока вывода Carlink просыпаются каждые 50 мс вместо каждых 5 мс и используют по 5 мс процессорного времени в секунду каждый вместо 24–27, примерно на 80% меньше.
  - Собственные экраны приложения компилируются заранее при установке, поэтому в первые несколько раз страницы открываются чуть быстрее: самый долгий кадр при открытии настроек — 80–96 мс вместо 99,6 мс.
  - В целом приложение в простое использует 220–234 мс процессорного времени в секунду вместо 245–336, на 10–30% меньше.
- Приложение для Android: сохраняет старые разрешения Bluetooth Android на Android 12 и новее. Некоторые телефоны с MIUI на Android 12 по-прежнему проверяют их, когда iPhone подключается по Bluetooth, и подключение сразу завершалось ошибкой.

**Примечания**

- Известная проблема: при открытии настроек один кадр по-прежнему задерживается на 80–96 мс (около пяти кадров при 60 кадр/с), прежде чем страница выезжает.
- Полные примечания к выпуску: [GitHub Releases](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.4).

## 0.2.3 {#v0-2-3}

2026-10-30 · [Скачать](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.3)

Приложение для Android: главный экран в виде кабелей, режим высокой производительности, работа в фоне, журналы, объясняющие зависания и прерывания, и эксперименты с беспроводным подключением на iOS 16.

**Новое**

- Приложение для Android: главный экран рисует подключение сверху вниз: iPhone, этот телефон и автомобиль соединены кабелями, которые заполняются по мере выполнения шагов, а на каждом кабеле указаны выполненные на нём шаги; собственные шаги этого телефона заполняют кольцо вокруг него. Значок есть только у шагов, которые требуют вашего участия (!) или завершились ошибкой (x), а на ручке панели шагов написано *Swipe up for all steps* с общим счётчиком.

2026-10-26 · [Скачать](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.0)

Приложение для Android: переработанное приложение, которое проверяет подключение шаг за шагом, выбор автомобиля по модели и году, настройки частоты кадров и размера изображения Carlink, настройки страницы головного устройства через значок OpenXPlay в CarPlay, экспорт журналов и проверка обновлений.

На главном экране три плитки, один заголовок и не более одного действия: *Connect*, исправление для текущего шага, *Retry* или *Start now*. Коснитесь плитки или потяните вверх панель внизу, чтобы увидеть все шаги, зачем они нужны и что делать, например включить Bluetooth, выполнить сопряжение с iPhone или ввести код Carlink. При сбое сообщается, что пошло не так и что делать, с кодом и временем. Страница работающего сеанса выглядит так же.

Браузер Tesla не открывает адреса локальной сети, поэтому, если выбрана Tesla, Settings → Car and screen → *Tesla browser* добавляет адрес на телефоне-ретрансляторе через локальный VPN (по умолчанию 169.254.88.1; ничего не покидает телефон). Есть четыре способа открыть страницу: доверенное имя или прямой адрес на этом локальном адресе канала либо адрес в стиле TeslaMirror или TeslaAndroid; способы с доверенным именем требуют [доверенного HTTPS](/ru/trusted-https) и открываются без предупреждения о сертификате. Нужны беспроводной CarPlay, вывод *Car browser* и точка доступа телефона-ретранслятора или Wi-Fi Direct; переключение между способами не прерывает CarPlay.

Страница головного устройства показывает и меняет ту же настройку. Изменение один раз перезапускает работающий сеанс. Настройка заменяет переопределение частоты кадров в параметрах разработчика; включённое переопределение переносится.

Размер, отмеченный звёздочкой, используется для каждого подключения; выбор другого пробует его только для текущего подключения и перезапускает CarPlay, если Carlink работает.

Они выезжают справа, с быстрыми плитками для звука, полноэкранного режима и заполнения, меню изображения, звука и микрофона, плагинов и сведений о программе, а также страницами выбора вместо раскрывающихся списков. - Файл конфигурации, экспортированный версией 0.2.0 с выбранным автомобилем, не импортируется в более старые версии; более старые файлы импортируются в 0.2.0.
- Если звук CarPlay идёт из iPhone, а не из автомобиля, выключите Settings → Sound → *CarPlay audio over the car’s Bluetooth* или оставьте iPhone в сопряжении с автомобилем и выберите Bluetooth источником звука в автомобиле.
- Полные примечания к выпуску: [GitHub Releases](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/android-v0.2.0).

## 0.1.3 {#v0-1-3}

2026-10-19 · [Скачать](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/tag/v0.1.3)

CarPlay подстраивается под окно браузера головного устройства без переподключения; добавлены модели автомобилей, разрешение Native и настройка ширины экрана CarPlay.

**Новое**

- Приложение для Android: области отображения CarPlay, включены по умолчанию. Когда браузер головного устройства входит в полноэкранный режим или выходит из него, переходит в режим разделённого экрана или возвращается в окно после камеры заднего вида, CarPlay перестраивает раскладку под новый размер без переподключения, а страница показывает только эту область, без чёрных полос.
- Приложение для Android: Settings → Car and screen. Выберите марку и модель автомобиля (встроенный XPeng G6 2023 или Other). Размеры экрана, которые обнаруживает ретранслятор, показываются там и используются при следующем запуске; владельцы автомобилей, которых нет в списке, могут скопировать данные своего экрана и отправить их разработчикам.
- Приложение для Android: экран последнего головного устройства запоминается, поэтому CarPlay подстраивается правильно, даже если запускается до открытия страницы головного устройства.
- Страница головного устройства (Android-ретранслятор): настройки Resolution (Automatic, Native, 1080p, 720p, Whole screen) и CarPlay screen width (125, 200, 250 или 300 мм, по умолчанию 200), также в настройках приложения. Native использует собственные пиксели головного устройства, когда его браузер может их декодировать; большая ширина экрана показывает больше значков на одной странице.
- Страница головного устройства (Android-ретранслятор): после выхода браузера из полноэкранного режима, например для камеры заднего вида, одно касание возвращает полноэкранный режим, не доходя до CarPlay; это можно выключить в настройках.
- Страница головного устройства (Android-ретранслятор): показывает версию страницы с коммитом и версию приложения и один раз перезагружается после обновления приложения.

**Изменения**

- Приложение для Android: главный экран показывает полный адрес `https://`, отмечает, что это https, а не http, и перечисляет только адреса, доступные головному устройству.
- Приложение для Android: при выборе точки доступа рекомендуется диапазон 5 ГГц, а мастер настройки прокручивает страницу к полям, которые ещё нужно заполнить.
- Приложение для Android: вывод Carlink помечен как экспериментальный и способный давать сбои.
- Приложение для Android: только английский и упрощённый китайский; частичные переводы на другие языки удалены.

**Примечания**
