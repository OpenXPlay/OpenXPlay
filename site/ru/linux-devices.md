# Linux-ретранслятор на других устройствах <Badge type="info" text="Для опытных" />

Помимо UFI003, Linux-ретранслятор OpenXPlay может работать на других устройствах arm64 Linux: одноплатных компьютерах, ТВ-приставках и USB-модемах. Эта страница предназначена для тех, кто уверенно работает с SSH и командной строкой. Здесь показано, как определить, может ли устройство запускать ретранслятор, как установить его вручную, как обновить и удалить. Как всегда, на головное устройство ничего не устанавливается.

У UFI003 есть собственный пошаговый установщик: см. [USB-модем UFI003 в роли ретранслятора](/ru/ufi003-relay). У Phicomm N1 тоже есть своё руководство: см. [Phicomm N1 в роли ретранслятора](/ru/phicomm-n1). OpenXPlay Flasher пока не умеет устанавливать ретранслятор на другие устройства.

::: warning На ваш страх и риск
Ручная установка ретранслятора на другое устройство выполняется на ваш страх и риск. Расскажите [сообществу](/ru/community), что сработало, а что нет, указав устройство, его систему и версию ретранслятора.
:::

## Требования {#requirements}

| Требование | Зачем это нужно | Как проверить | |
| --- | --- | --- | --- |
| 64-битный ARM (aarch64) | Выпуски собираются только для aarch64. Это статические исполняемые файлы musl, поэтому версия glibc или Debian для них не важна. | `uname -m` выводит `aarch64`; для `.deb` команда `dpkg --print-architecture` выводит `arm64` | Обязательно |
| systemd в качестве init | Ретранслятор работает как служба systemd `openxplay-relay.service`. | `ps -p 1 -o comm=` выводит `systemd` | Обязательно |
| NetworkManager | `nmcli` создаёт все точки доступа и подключения Wi-Fi; его режим shared вместе с `dnsmasq-base` раздаёт адреса (DHCP). | `systemctl is-active NetworkManager` | Обязательно |
| BlueZ | Ретранслятор использует `bluetoothd` через D-Bus и утилиты `sdptool`, `hciconfig` и `btmgmt`. | `systemctl is-active bluetooth`; `command -v sdptool hciconfig btmgmt` | Обязательно для беспроводного подключения и Carlink |
| `iw` | С его помощью ретранслятор считывает режимы, каналы и страну адаптера Wi-Fi. | `command -v iw` | Обязательно |
| Bluetooth Classic (BR/EDR) | Беспроводной CarPlay передаёт iAP2 по RFCOMM — протоколу Bluetooth Classic. Адаптер только с Bluetooth Low Energy не может подключить iPhone без проводов. | `btmgmt info` показывает `br/edr` | Обязательно для беспроводного подключения |
| RFCOMM в ядре | По той же причине. В ядре UFI003 его не было; пакет устройства добавляет `rfcomm.ko`. | `sudo modprobe rfcomm` | Обязательно для беспроводного подключения |
| Wi-Fi, способный работать точкой доступа (режим AP) | Он нужен для собственной точки доступа ретранслятора — сети по умолчанию. | `iw list` показывает `AP` в *Supported interface modes* | Обязательно |
| Свободные порты | 6975 TCP (страница администрирования), 8443 TCP (страница головного устройства), от 7000 и выше (AirPlay), 5353 UDP (mDNS, на который ретранслятор отвечает сам). | `ss -ltnup` | Обязательно |
| Идентификатор аксессуара Apple (MFi) | Без него ретранслятор отдаёт только страницу администрирования. | Вы предоставляете его сами; см. [Добавьте идентификатор CarPlay](#identity) | Обязательно |
| Wi-Fi 5 ГГц | Автоматический выбор диапазона использует 5 ГГц, когда точку доступа можно разместить на канале 5 ГГц, иначе 2,4 ГГц, канал 6. Одного диапазона 2,4 ГГц достаточно (UFI003 работает с CarPlay на нём); установите частоту кадров 30 на странице головного устройства. | `iw list`; `iw reg get` | Не обязательно |
| Второй адаптер Wi-Fi, способный быть клиентом в сети 5 ГГц | В реальном автомобиле для Carlink ретранслятор должен подключаться к Wi-Fi 5 ГГц автомобиля как клиент через адаптер, на котором не работает точка доступа для iPhone. С одним адаптером Wi-Fi ретранслятор предлагает только вывод в браузер. Carlink также использует Bluetooth LE; Wi-Fi Direct не обязателен. | `nmcli device`; `btmgmt info` показывает `le` | Обязательно для Carlink |
| USB-порт хоста (USB-A) с поддержкой usbfs и TUN/TAP в ядре | При кабельном подключении iPhone подключается к порту USB-A на ретрансляторе; ретранслятор управляет им через usbfs и передаёт сетевой трафик CarPlay через виртуальный интерфейс TAP. | `ls /dev/bus/usb /dev/net/tun` | Обязательно для USB |

Сам ретранслятор невелик. 2026-10-15 первая сборка для разработчиков Linux-ретранслятора на Rust, простаивая на UFI003 (382 МБ ОЗУ) без сеанса CarPlay, занимала около 2,9 МБ резидентной памяти плюс 1,5 МБ на процесс вывода и около 5 МБ на диске.

| Система | |
| --- | --- |
| Debian 11 (bullseye), 12 (bookworm) и 13 (trixie) | `.deb` протестирован на каждой |
| OpenStick Debian 11 на UFI003 (NetworkManager 1.30, BlueZ 5.55) | Используется |
| Armbian trixie на Phicomm N1 (NetworkManager 1.52, BlueZ 5.82) | Используется |
| Debian 13 на Raspberry Pi 5 | Эталонная плата разработчиков; пакета устройства для неё пока нет |

::: details Команды для проверки устройства {#check}
Выполните их на устройстве через SSH. Команды с `sudo` требуют прав root.

```sh
uname -m; dpkg --print-architecture; . /etc/os-release; echo "$ID $VERSION_ID"
ps -p 1 -o comm=
systemctl is-active NetworkManager bluetooth
nmcli --version
nmcli device
command -v nmcli iw sdptool hciconfig btmgmt
sudo iw list
sudo iw reg get
printf '' | sudo btmgmt --index 0 info
sudo modprobe rfcomm && lsmod | grep rfcomm
ls /dev/bus/usb /dev/net/tun
ss -ltnup | grep -E ':(6975|8443|7000|5353)\b'
```

| Команда | Что искать |
| --- | --- |
| `uname -m`, `dpkg --print-architecture` | `aarch64` и `arm64`; остальная часть строки выводит дистрибутив и его версию |
| `ps -p 1 -o comm=` | `systemd` |
| `systemctl is-active` | `active` дважды |
| `nmcli device` | Интерфейсы Wi-Fi (тип `wifi`); для имени, отличного от `wlan0`, нужен [профиль хоста](#host-profile) |
| `command -v` | По одному пути на каждую утилиту; отсутствующая строка означает отсутствующую утилиту |
| `iw list` | `AP` в *Supported interface modes*; каналы 5 ГГц и их флаги |
| `iw reg get` | Страна Wi-Fi, которая задаёт флаги каналов |
| `btmgmt info` | `br/edr` в *supported settings* и `le` для Carlink |
| `modprobe rfcomm` | `rfcomm` в списке модулей; это лишь подсказка |
| `ls` | Оба пути существуют; нужно только для подключения iPhone кабелем |
| `ss` | Ничего, или только программы, которые можно остановить |

Для собственной точки доступа ретранслятор пробует каналы 5 ГГц 36, 40, 44, 48 и со 149 по 165. Канал может нести точку доступа, только если `iw list` не помечает его как disabled, no IR или radar detection; для подключения к сети 5 ГГц достаточно, чтобы канал не был disabled. Если ни один канал 5 ГГц не подходит, ретранслятор использует канал 6 в диапазоне 2,4 ГГц.

Не убирайте пустой `printf` в строке с `btmgmt`: `btmgmt` зависает, когда его ввод — `/dev/null`. `--index 0` — это первый адаптер, `hci0`.

После установки раздел **Diagnostics → This host** на странице администрирования показывает, что находит сам ретранслятор: RFCOMM; Bluetooth BR/EDR, LE и Secure Connections; поддержку режимов AP и клиента для каждого интерфейса; каналы 5 ГГц, на которых можно разместить точку доступа; страну Wi-Fi; отсутствующие утилиты. Доверяйте этим данным больше, чем этим командам.
:::

## Установите ретранслятор {#install .step}

Возьмите самый новый выпуск `linux-v` из [Releases](https://github.com/OpenXPlay/OpenXPlay-Relay/releases); сейчас это `linux-v0.1.6`. Скачайте `.deb` и `SHA256SUMS`, проверьте SHA-256, затем установите пакет вместе с зависимостями:

```sh
V=0.1.6
base=https://github.com/OpenXPlay/OpenXPlay-Relay/releases/download/linux-v$V
curl -fL -O "$base/openxplay-relay_${V}_arm64.deb" -O "$base/SHA256SUMS"
sha256sum --ignore-missing -c SHA256SUMS
sudo apt-get install --no-install-recommends ./openxplay-relay_${V}_arm64.deb
```

Задайте в `V` самую новую версию. В именах файлов предварительная версия записывается как `0.1.7-beta.1`; внутри пакета её версия — `0.1.7~beta.1`.

`apt-get` также устанавливает `bluez`, `network-manager`, `iw`, `dnsmasq-base` и `init-system-helpers` версии 1.54 или новее. Пакет:

- устанавливает ретранслятор в `/opt/openxplay`;
- добавляет службу systemd `openxplay-relay.service`, которая включается и запускается при первой установке;
- добавляет команду обновления `/usr/sbin/openxplay-relay-update`;
- добавляет два файла конфигурации NetworkManager: энергосбережение Wi-Fi выключено, случайный MAC-адрес при сканировании не используется;
- добавляет защиту часов, которая работает с systemd-timesyncd и ничего не делает при chrony.

При удалении пакета `/var/lib/openxplay` сохраняется.

::: details Установка из архива tar {#tarball}
Скачайте `openxplay-relay-<version>-linux-aarch64.tar.gz` и `SHA256SUMS` из того же выпуска и проверьте их. Архив не устанавливает зависимости, поэтому сначала установите `bluez`, `network-manager`, `iw` и `dnsmasq-base`. Затем:

```sh
tar -xzf openxplay-relay-$V-linux-aarch64.tar.gz
cd openxplay-relay-$V-linux-aarch64
sudo sh rust/packaging/install.sh bin/openxplay-relay bin/oxp-relay web admin
```
:::

::: details Wi-Fi называется не wlan0? Добавьте профиль хоста {#host-profile}
Ретранслятор читает необязательный профиль хоста `/etc/openxplay/host.json`. Обычно его записывает пакет устройства; на других устройствах его можно написать самостоятельно. Все поля необязательны:

| Поле | По умолчанию |
| --- | --- |
| `model` | Нет |
| `devicePreset` | `auto`: определяет модемы MSM8916 и Phicomm N1 по дереву устройств, иначе `generic` |
| `wifiInterface` | `wlan0` |
| `carlinkInterface` | Пусто: другой адаптер Wi-Fi, выбирается автоматически |
| `hotspotChannel` | `0`: автоматически |
| `bluetoothAdapter` | `hciN` с наименьшим номером |
| `hotspotDownGapSeconds` | `15` (от 0 до 60): сколько точка доступа остаётся выключенной, прежде чем запустится следующая |
| `secureConnections` | `pairing-off`: Bluetooth Secure Connections выключены только на время открытого сопряжения; либо `untouched` |
| `bluetoothGuardStatus` | `/run/openxplay/bluetooth-guard.json` |

Например, для Wi-Fi на `wlan1`:

```sh
sudo mkdir -p /etc/openxplay
echo '{"wifiInterface": "wlan1"}' | sudo tee /etc/openxplay/host.json
sudo systemctl restart openxplay-relay
```

Одно недопустимое поле заставляет ретранслятор игнорировать весь файл и показывать ошибку на странице администрирования. Настройки применяются в таком порядке, и каждая следующая переопределяет предыдущую: встроенные значения по умолчанию, профиль хоста, настройки страницы администрирования, командная строка.
:::

## Откройте страницу администрирования {#admin .step}

На телефоне или компьютере в той же сети, что и устройство, откройте `https://<IP устройства>:6975` (`hostname -I` на устройстве выводит его адреса). Там, где разрешаются имена `.local`, работает и `https://openxplay-admin.local:6975`, а с телефона в точке доступа ретранслятора — `https://openxplay-car.local:6975`; многие телефоны на Android и браузеры автомобилей их не разрешают. Браузер предупреждает о самоподписанном сертификате ретранслятора; перейдите на страницу. Начальный пароль — `openxplay`: войдите, затем смените его.

Дополнительная точка доступа администрирования `OpenXPlay-Admin` по умолчанию выключена и требует второго адаптера Wi-Fi. Включив её на странице администрирования, подключитесь к ней и откройте `https://openxplay-admin.local:6975` или `https://10.79.0.1:6975`.

::: details Забыли пароль администратора? {#reset-password}
```sh
sudo systemctl stop openxplay-relay
sudo /opt/openxplay/bin/openxplay-relay --reset-admin-password
sudo systemctl start openxplay-relay
```

Вторая команда сбрасывает пароль на `openxplay` и завершается.
:::

## Добавьте идентификатор CarPlay {#identity .step}

Установочные пакеты никогда не содержат идентификатора аксессуара Apple (MFi); вы предоставляете собственный. На странице администрирования откройте **Settings → Identity and certificates** и выберите `identity.pk8` и `certificate.p7b` или ZIP-архив, содержащий оба файла.

Либо разместите файлы вручную, с владельцем root и режимом 0600, и перезапустите ретранслятор:

```sh
sudo install -D -m 0600 -o root -g root -t /var/lib/openxplay/mfi identity.pk8 certificate.p7b
sudo systemctl restart openxplay-relay
```

Если этих двух файлов нет, но есть другой источник аутентификации, выберите удалённый сервер MFi или чип аутентификации по I2C или через адаптер CH341 в **Settings → Identity and certificates → MFi target**.

## Ответьте на вопросы мастера настройки {#setup .step}

Мастер настройки на странице администрирования спрашивает:

1. **Ваш автомобиль**.
2. **Вывод**: браузер головного устройства, его приложение Carlink или оба. Для Carlink нужен второй адаптер Wi-Fi; с одним адаптером предлагается только браузер. Браузеру Tesla требуется отдельная адаптация; см. [Tesla](/ru/tesla). [Беспроводной дисплей](/ru/wireless-display) и [CarLife](/ru/carlife) в Linux недоступны.
3. **Подключение iPhone**: *Wireless* (по умолчанию) или *USB cable*, когда iPhone подключён к порту USB-A на ретрансляторе кабелем USB-A — Lightning или USB-A — USB-C; головное устройство при этом по-прежнему связывается с ретранслятором по Wi-Fi.
4. **Сеть**: *This relay’s hotspot* или *Use the car’s hotspot*. Собственная точка доступа ретранслятора — `OpenXPlay-Linux-XXXX` с паролем `openxplay` (WPA2), если вы не задали свой.
5. **Подготовка**: выполните всё, что указано в списке.

## Выполните сопряжение с iPhone {#pair .step}

Когда главный экран предложит выполнить сопряжение с iPhone, нажмите *Pair*; сопряжение остаётся открытым 10 минут. На iPhone откройте «Настройки» → Bluetooth и выберите `OpenXPlay Linux`.

Чтобы перейти на другой iPhone или выполнить сопряжение заново: удалите старое сопряжённое устройство на главном экране или в Settings → iPhone connection, забудьте `OpenXPlay Linux` в настройках Bluetooth на iPhone, затем снова откройте сопряжение.

## Откройте CarPlay на головном устройстве {#head-unit .step}

Подключите головное устройство к точке доступа ретранслятора и откройте в его браузере `https://10.77.0.1:8443/`. Ретранслятор берёт первый свободный адрес `10.77.x.1`, а страница администрирования показывает адрес для головного устройства; при *Use the car’s hotspot* откройте указанный там адрес. В первый раз примите предупреждение о сертификате; почему оно появляется, объясняет раздел [Решение проблем](/ru/troubleshooting#certificate-warning).

О приложении Carlink см. [Приложение Carlink](/ru/carlink).

## Обновление ретранслятора {#update}

На странице администрирования **About → Check for updates** показывает, есть ли более новая версия; выберите канал *Beta*, чтобы видеть и предварительные выпуски. Скачайте новый `.deb` и `SHA256SUMS` и проверьте их, как в разделе [Установите ретранслятор](#install), затем выполните:

```sh
sudo openxplay-relay-update openxplay-relay_${V}_arm64.deb
```

Команда обновления устанавливает новую версию, ждёт запуска ретранслятора и наблюдает за ним 15 секунд, чтобы убедиться, что он не завершается и не перезапускается; если новая версия не запускается, команда возвращает предыдущую. Настройки, сопряжения и идентификатор хранятся в `/var/lib/openxplay` и остаются без изменений.

| Команда | Что делает |
| --- | --- |
| `sudo openxplay-relay-update --list` | Показывает кешированные версии |
| `sudo openxplay-relay-update --rollback` | Возвращает самую новую кешированную версию, которая старше текущей |

Версии, установленные командой обновления, кешируются в `/var/cache/openxplay/relay`, не более 3. Для отката в кеше должна быть и текущая версия; первой версии, установленной через `apt-get`, там нет.

## Журналы и удаление {#uninstall}

Прочитайте журнал ретранслятора с момента загрузки или следите за ним в реальном времени:

```sh
journalctl -u openxplay-relay -b
journalctl -u openxplay-relay -f
```

Чтобы сообщить о проблеме, экспортируйте журналы в разделе **Logs** на странице администрирования.

Удаление ретранслятора:

```sh
sudo apt-get purge openxplay-relay
```

Настройки, сопряжения, ключи и идентификатор в `/var/lib/openxplay` сохраняются; удалите их командой `sudo rm -rf /var/lib/openxplay`, когда они вам больше не понадобятся.

## Не поддерживается {#not-supported}

| Устройство или система | Причина |
| --- | --- |
| OpenWrt и другие системы без systemd или NetworkManager | Ретранслятору нужны оба |
| Платы на 32-битном ARM (armv7), x86 и RISC-V | Сборок для них нет |
| Адаптеры Bluetooth только с Bluetooth Low Energy | Беспроводному CarPlay нужен Bluetooth Classic (RFCOMM); для кабельного подключения Bluetooth не нужен |
| ESP32 и другие микроконтроллеры | На них не работает Linux |
