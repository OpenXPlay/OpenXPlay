## 已经实现，还没在车上测过 {#not-tested}

- **特斯拉浏览器**：安卓应用 0.2.0 起、Linux 中继 0.1.6 起提供，见[特斯拉](/tesla)。
- **Linux 中继的 Carlink**：Linux 中继 0.1.6 起，用第二块 Wi-Fi 网卡连接车机，见 [Carlink 应用](/carlink)。
- **无线投屏（DLNA、Miracast）**：安卓测试版 0.2.5-beta.1 起可以选择，只显示画面，不能触控。
- **车型目录**：应用“设置 → 车型与屏幕”里的小鹏各车系、特斯拉和极氪用来选择屏幕数据，列在目录里不代表测过。

你的车不在表中？在车机浏览器中打开[检测车机](/check)，把报告连同车型、车机系统版本和中继版本发到[交流群](/community)。检测只说明浏览器提供了所需的功能，不算在车上测过。

### 推荐设置 {#xpeng-g6-setup}

- **怎么选：** 两条路线在车上都显示过画面。浏览器路线测得更多，使用安卓中继时可以全屏；Carlink 路线用车机自带的 Carlink 应用，仍是实验性功能。
- **浏览器路线：** 推荐用安卓中继，并在“设置 → 车型与屏幕”中选择小鹏 G6 2023 款。中继只有 2.4 GHz Wi-Fi 时（例如 UFI003），在网页接收端的设置中把帧率设为 30。使用 H.265 时画面迟迟不出现，就把“视频编码”改为“强制 H.264”。
- **Carlink 路线：** 使用安卓应用 0.1.5 或更新版本（[下载最新版本](https://github.com/OpenXPlay/OpenXPlay-Relay/releases/latest/download/openxplay-relay.apk)），中继手机需要支持 5 GHz Wi-Fi（Carlink 需要 Android 10 及以上），第一次连接时在中继中输入车机屏幕上的配对码。“视频编码”保持“自动”，中继会直接发送 H.265 画面。

### 浏览器（网页接收端） {#xpeng-g6-browser}

小鹏 G6 内置基于 Chromium 120 的浏览器，支持 WebCodecs。下面的能力是浏览器自己报告的，和[检测车机](/check)报告的项目相同：H.264（Baseline、Main、High）和 H.265 在 720p 和 1080p、30 和 60 帧/秒下都报告为硬件解码。屏幕为 1372×686 CSS 像素。浏览器不全屏时，网页可用约 876×518；进入全屏后，网页有时占满整块屏幕，有时为 876×579；分屏时约 489×579。浏览器报告支持 5 点触控和 AudioWorklet（在浏览器中播放 CarPlay 声音要用到），在车上还没有测过声音。

- **视频格式：** 2026-10-16 用 UFI003 上的 Linux 中继测试时，H.264 最可靠：使用 H.265 时，中途打开或刷新网页后曾要等 40 多秒才出现画面。Linux 中继之后加入了画面等太久就改用 H.264 的处理，还没有在车上复测；安卓中继在这台车的浏览器上使用 H.265 还没有测试记录。
- **帧率：** 中继只有 2.4 GHz Wi-Fi 时（例如 UFI003），请在网页接收端的设置中把帧率设为 30。2026-10-15—16 的测试中，经 2.4 GHz 连接以 60 帧/秒播放会卡顿；30 帧/秒明显更流畅，偶尔仍有轻微卡顿。
- **全屏与倒车：** 使用安卓中继时，网页默认全屏。倒车影像会让浏览器退出全屏，这台车的浏览器不允许网页自动恢复（2026-10-18）；回到网页后轻触一下恢复全屏，当前版本的问题见[已知问题](/daily-use#fullscreen-known-issue)。
- **车型设置：** 在安卓中继的“设置 → 车型与屏幕”中选择小鹏 G6 2023 款，中继会使用内置的屏幕数据，让 CarPlay 画面贴合全屏、窗口和分屏，切换时不用重新连接。

::: details 浏览器参数 {#xpeng-g6-browser-details}
2026-10-16 OpenXPlay 从车机浏览器读取到的信息。[检测车机](/check)会报告同类项目，可以拿来对照。

| 项目 | 结果 |
| --- | --- |
| 浏览器 | Chromium 120.0.6099.144（用户代理自称桌面版 Linux x86_64） |
| 图形处理器 | Qualcomm Adreno 640（经 ANGLE），OpenGL ES 3.2；最大纹理尺寸 4096；不提供 WebGPU |
| 处理器 | 8 核 |
| 内存 | 报告的设备内存为 8 GB；JavaScript 堆上限约 1.1 GB |
| 屏幕 | 1372×686 CSS 像素，设备像素比 1.75（约 2400×1200 物理像素），横屏，59.9 Hz |
| 浏览器窗口 | 不全屏时 876×518 CSS 像素；全屏时 1372×686 或 876×579；分屏时约 489×579 |
| 触控 | 5 个触摸点 |
| Web API | WebCodecs（VideoDecoder、VideoFrame）、OffscreenCanvas、requestVideoFrameCallback、AudioWorklet；安全上下文 |
| 音频 | AAC 和 Opus 解码器；采样率 48 kHz；基础延迟 5 ms |
:::

::: details 视频解码 {#xpeng-g6-browser-video}
下表中的格式在 30 和 60 帧/秒下都受支持。

| 格式 | 1280×720 | 1920×1080 |
| --- | --- | --- |
| H.264 Baseline | 硬件解码 | 硬件解码 |
| H.264 Main | 硬件解码 | 硬件解码 |
| H.264 High | 硬件解码 | 硬件解码 |
| H.265 Main | 硬件解码 | 硬件解码 |

“硬件解码”表示浏览器报告可以低功耗解码这种格式，通常意味着由硬件解码器处理。

- 浏览器报告的“流畅”（smooth）标志不可靠：它把 720p、30 帧/秒的 H.264 High 报告为不流畅，却把 60 帧/秒和 1080p 报告为流畅。
- 实测解码延迟：H.264 每帧约 33–59 ms，H.265 约 28 ms。这是硬件解码器的流水线延迟，并不说明解码速度跟不上。
:::

### Carlink 应用 {#xpeng-g6-carlink}

已用安卓中继的开发版在车上测试，可以显示画面（实验性），逐项结果见[测试结果](#xpeng-g6-results)。安卓应用 0.1.3 及更早的版本在这台车上有声音但画面全黑，0.1.5 修复了这个问题。车机为 Carlink 建立自己的 5 GHz Wi-Fi，中继加入这个网络，因此中继需要支持 5 GHz Wi-Fi。UFI003 不能用 Carlink；Linux 中继用第二块 Wi-Fi 网卡运行 Carlink，还没有在这台车上测过。

::: details Carlink 视频支持 {#xpeng-g6-carlink-video}
| 项目 | 车机的 Carlink 应用 |
| --- | --- |
| H.264 | 仅 Constrained Baseline，不支持 Constrained High；级别 3.1 |
| 原生视频模式 | 1280×720，逐行扫描，30 帧/秒 |
| H.265 | 车机声明支持（`iccoa_support_hevc`），可以直接显示 iPhone 的 H.265 画面，实测最高约 58 帧/秒 |
| 显示尺寸 | Carlink 窗口（三分之二屏）为 1532×1013，240 dpi，与 1280×720 的视频模式不同。安卓应用 0.1.5 起，CarPlay 按这个窗口的比例显示，H.265 直接以约 1532×1014 发送；车机按收到的画面尺寸换算触控。会话中切换到全屏时，车机不会告诉中继新尺寸 |
| 媒体音频 | AAC |

向 iPhone 请求的编码和 Carlink 会话的编码不一定相同。这台车声明支持 H.265，开发者选项中的“Carlink H.265”保持“自动（推荐）”时，Carlink 会话从头到尾只用 H.265：“视频编码”为“自动”时，中继把 iPhone 的 H.265 画面原样发给车机（格式和尺寸都合适时），手机不用转码；如果 iPhone 发出的是 H.264（例如设为“强制 H.264”），中继会把它转换为 H.265。

只有把“Carlink H.265”设为“关闭”时，会话才用 H.264：iPhone 发出的 H.264 High 车机的 Carlink 应用无法显示，中继会把它转换为 H.264 Constrained Baseline 3.1，尺寸按 Carlink 窗口的比例缩小到这个级别允许的范围，安卓中继用硬件编码器完成转换。
:::

::: details 连接与配对 {#xpeng-g6-carlink-connection}
| 项目 | 情况 |
| --- | --- |
| Wi-Fi | 车机为 Carlink 建立自己的 5 GHz Wi-Fi，中继加入这个网络，因此中继需要支持 5 GHz Wi-Fi，并且 Wi-Fi 要保持打开。无线 CarPlay 使用“此手机的热点”时，安卓中继同时开 5 GHz 热点并用 Wi-Fi 连接车机，实测连续约一小时稳定。 |
| 配对 | 第一次连接时，在中继中输入车机屏幕上显示的配对码。中继会记住配对，之后通常不用再输入；但车机开机后的自动连接还要在这台车上复测，可能需要先打开车机 Carlink 应用的配对码页面。 |
| 车辆信息 | 已在这个 Carlink 版本上测试（2026-10-20）：车机接受了车辆信息连接，但换挡、开关车灯和切换日夜主题后都没有发来数据。 |
:::

## 小鹏 P7+ {#xpeng-p7-plus}

2026-10-31，一位车主用安卓应用 0.2.3（Android 15 手机）连接 Carlink，没有出现 CarPlay 画面：车机和中继建立了 Carlink 连接，但 iPhone 一直没有开始向中继发送画面。同一部手机用“此手机的热点”时也出现过同样的问题，所以原因不一定在车上，还在调查。年款、车机系统和 Carlink 版本没有记录。
