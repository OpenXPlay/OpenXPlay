# 车机资料

本页记录 OpenXPlay 实测过的车机：车机的浏览器和 Carlink 应用能否显示 CarPlay、能解码哪些视频格式，以及怎样设置效果最好。所有结果都来自 OpenXPlay 自己的测试；同一款车在不同系统版本上可能有所不同。

| 车机 | 浏览器 | Carlink 应用 | 测试时间 |
| --- | --- | --- | --- |
| [小鹏 G6](#xpeng-g6)（2023 款） | 可以，H.264 和 H.265 都能硬件解码 | 可以（实验性），需要安卓应用 0.1.5 或更新版本 | 2026 年 10 月 |

你的车机不在表中？在车机浏览器中打开[检测车机](/check)测试，并把结果分享到[交流群](/community)。

## 小鹏 G6 {#xpeng-g6}

2026 年 10 月测试，车型为 2023 款。

| 路线 | 可用 | 说明 |
| --- | --- | --- |
| 浏览器 | 可以 | 已用安卓中继和 UFI003 USB 随身 Wi-Fi 上的 Linux 中继测试。内置 Chromium 120 浏览器，H.264 和 H.265 都能硬件解码。使用安卓中继时网页可以全屏；倒车后浏览器会退出全屏，轻触一下即可恢复。 |
| Carlink | 可以（实验性） | 已用安卓中继测试。安卓应用 0.1.5 起可以显示画面，更早的版本会黑屏。车机声明支持 H.265，中继直接发送 iPhone 的 H.265 画面，不用转码。中继需要支持 5 GHz Wi-Fi。 |

### 推荐设置 {#xpeng-g6-setup}

- **怎么选：** 两条路线都可以用。浏览器路线更成熟，使用安卓中继时可以全屏；Carlink 路线用车机自带的 Carlink 应用，仍是实验性功能。
- **浏览器路线：** 推荐用安卓中继，并在“设置 → 车型与屏幕”中选择小鹏 G6 2023 款。中继只有 2.4 GHz Wi-Fi 时（例如 UFI003），在网页接收端的设置中把帧率设为 30。视频格式目前以 H.264 最可靠。
- **Carlink 路线：** 使用安卓应用 0.1.5 或更新版本，中继手机需要支持 5 GHz Wi-Fi（Carlink 需要 Android 10 及以上），第一次连接时在中继中输入车机屏幕上的配对码。“视频编码”保持“自动”，中继会直接发送 H.265 画面。

### 浏览器（网页接收端） {#xpeng-g6-browser}

小鹏 G6 内置基于 Chromium 120 的浏览器，支持 WebCodecs。H.264（Baseline、Main、High）和 H.265 在 720p 和 1080p、30 和 60 帧/秒下都能硬件解码。屏幕为 1372×686 CSS 像素。浏览器不全屏时，网页可用约 876×518；进入全屏后，网页有时占满整块屏幕，有时为 876×579；分屏时约 489×579。浏览器支持 5 点触控，也支持 AudioWorklet，CarPlay 的声音可以在浏览器中播放。

- **视频格式：** 目前 H.264 最可靠。这台车也能硬件解码 H.265，但使用 H.265 时，中途打开或刷新网页后可能要等较长时间才出现画面，这个问题仍在修复。
- **帧率：** 中继只有 2.4 GHz Wi-Fi 时（例如 UFI003），请在网页接收端的设置中把帧率设为 30。测试中，经 2.4 GHz 连接以 60 帧/秒播放会卡顿；30 帧/秒明显更流畅，偶尔仍有轻微卡顿。
- **全屏与倒车：** 使用安卓中继时，网页默认全屏。倒车影像会让浏览器退出全屏，回到网页后轻触一下即可恢复；这台车的浏览器不允许网页自动恢复全屏。
- **车型设置：** 在安卓中继的“设置 → 车型与屏幕”中选择小鹏 G6 2023 款，中继会使用内置的屏幕数据，让 CarPlay 画面贴合全屏、窗口和分屏，切换时不用重新连接。

::: details 浏览器参数 {#xpeng-g6-browser-details}
测试时 OpenXPlay 从车机浏览器读取到的信息。[检测车机](/check)会报告同类项目，可以拿来对照。

| 项目 | 结果 |
| --- | --- |
| 浏览器 | Chromium 120.0.6099.144（用户代理自称桌面版 Linux x86_64） |
| 图形处理器 | Qualcomm Adreno 640（经 ANGLE），OpenGL ES 3.2；最大纹理尺寸 4096；不提供 WebGPU |
| 处理器 | 8 核 |
| 内存 | 报告的设备内存为 8 GB；JavaScript 堆上限约 1.1 GB |
| 屏幕 | 1372×686 CSS 像素，设备像素比 1.75（约 2400×1200 物理像素），横屏，59.9 Hz |
| 浏览器窗口 | 不全屏时 876×518 CSS 像素；全屏时 1372×686 或 876×579；分屏时约 489×579 |
| 触控 | 5 个触摸点 |
| Web API | WebCodecs（VideoDecoder、VideoFrame）、OffscreenCanvas、requestVideoFrameCallback、AudioWorklet；安全上下文 |
| 音频 | AAC 和 Opus 解码器；采样率 48 kHz；基础延迟 5 ms |
:::

::: details 视频解码 {#xpeng-g6-browser-video}
下表中的格式在 30 和 60 帧/秒下都受支持。

| 格式 | 1280×720 | 1920×1080 |
| --- | --- | --- |
| H.264 Baseline | 硬件解码 | 硬件解码 |
| H.264 Main | 硬件解码 | 硬件解码 |
| H.264 High | 硬件解码 | 硬件解码 |
| H.265 Main | 硬件解码 | 硬件解码 |

“硬件解码”表示浏览器报告可以低功耗解码这种格式，通常意味着由硬件解码器处理。

- 浏览器报告的“流畅”（smooth）标志不可靠：它把 720p、30 帧/秒的 H.264 High 报告为不流畅，却把 60 帧/秒和 1080p 报告为流畅。
- 实测解码延迟：H.264 每帧约 33–59 ms，H.265 约 28 ms。这是硬件解码器的流水线延迟，并不说明解码速度跟不上。
:::

### Carlink 应用 {#xpeng-g6-carlink}

已用安卓中继测试，可以使用（实验性）。0.1.3 及更早的版本在这台车上有声音但画面全黑，安卓应用 0.1.5 修复了这个问题。车机为 Carlink 建立自己的 5 GHz Wi-Fi，中继加入这个网络，因此中继需要支持 5 GHz Wi-Fi，只有 2.4 GHz 的 UFI003 无法连接。

::: details Carlink 视频支持 {#xpeng-g6-carlink-video}
| 项目 | 车机的 Carlink 应用 |
| --- | --- |
| H.264 | 仅 Constrained Baseline，不支持 Constrained High；级别 3.1 |
| 原生视频模式 | 1280×720，逐行扫描，30 帧/秒 |
| H.265 | 车机声明支持（`iccoa_support_hevc`），可以直接显示 iPhone 的 H.265 画面，最高约 60 帧/秒 |
| 显示尺寸 | Carlink 窗口（三分之二屏）为 1532×1013，240 dpi，与 1280×720 的视频模式不同。安卓应用 0.1.5 起，CarPlay 按这个窗口的比例显示，H.265 直接以约 1532×1014 发送；车机按收到的画面尺寸换算触控。会话中切换到全屏时，车机不会告诉中继新尺寸 |
| 媒体音频 | AAC |

安卓应用 0.1.5 起，“视频编码”为“自动”时，中继把 iPhone 的 H.265 画面原样发给车机，手机不用转码。使用 H.264 时，iPhone 发出的 H.264 High 车机的 Carlink 应用无法显示，中继会把它转换为 H.264 Constrained Baseline 3.1，尺寸按 Carlink 窗口的比例缩小到这个级别允许的范围，安卓中继用硬件编码器完成转换。
:::

::: details 连接与配对 {#xpeng-g6-carlink-connection}
| 项目 | 情况 |
| --- | --- |
| Wi-Fi | 车机为 Carlink 建立自己的 5 GHz Wi-Fi，中继加入这个网络，因此中继需要支持 5 GHz Wi-Fi，并且 Wi-Fi 要保持打开。只有 2.4 GHz 的 UFI003 无法连接。无线 CarPlay 使用“此手机的热点”时，安卓中继同时开 5 GHz 热点并用 Wi-Fi 连接车机，实测连续约一小时稳定。 |
| 配对 | 第一次连接时，在中继中输入车机屏幕上显示的配对码；之后会自动重新连接。 |
| 车辆信息 | 通过 Carlink 获取车辆信息尚未测试。 |
:::
